## Cause

The empty-workspace deterministic framework game fallback was too narrow:

- It ran only after a no-edit repo-change retry path, so it did not materialize immediately at the start of Act mode.
- Once the model wrote a sparse framework shell (`package.json` / `nuxt.config.ts`) without the primary UI file, `workspace_appears_empty()` became false.
- The loop then depended on the model to continue into `app.vue`; qwen3.5 stalled during that generation step.

## Fix Direction

- Run the deterministic framework game fallback before the first LLM Act request when a repo-changing game app request starts in an empty workspace.
- Treat sparse framework shells as eligible for deterministic materialization when the primary implementation file is still missing.
- Keep the guard generic by checking deterministic framework file sets rather than hard-coding only Nuxt.
