# uat_070

- 事象
  - qwen3.6 `uat_070` が `transport_error` で停止した。
  - Plan 承認後、`npx create-next-app@latest . ...` による scaffold と `app/page.tsx` の `Read` までは成功した。
  - focused edit recovery に入り、native `Edit` tool call のみを許可した `/api/chat` が Ollama 側で 500 を返した。

- 問題箇所
  - `src/agent/loop_run/turn.rs`
  - native tools 有効時の `/api/chat` transport error recovery。

- 根本原因
  - Ollama の qwen3.6 native tools テンプレートが `{"error":"XML syntax error on line 4: element <function> closed by </parameter>"}` を返し、モデル応答を生成する前に 500 で失敗した。
  - Anvil は native parser failure では native tools を無効化して再試行できるが、native tools 由来の `/api/chat` 5xx では同じ native tools 経路を再試行し、最終的に `transport_error` で終了した。

- 対策案
  - native tools 有効時に `/api/chat` 5xx が返った場合、そのセッションでは native tools を無効化し、既存の XML/generate fallback 経路で再試行する。

- 対策案詳細（仕様）
  - `native_tools_enabled == true`
  - まだ native tools downgrade を行っていない
  - error が `Ollama /api/chat failed: 5xx`
  - 上記を満たす場合、通常の transport retry より前に `disable_native_tools_for_session()` を実行して retry する。
  - 429 や通常の接続失敗は従来の transport retry に残す。
