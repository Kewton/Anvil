# uat-v3_008

## Scenario

- v3 scenario 02
- model: `qwen3.5:122b`
- instructions:
  - Next.js task manager on port 3011
  - React.js inquiry board on port 3011
  - Nuxt.js simple CRM on port 3011

## Result

Failed.

## Observed Failure

- Next.js run scaffolded the default app, then ended with `transport_error` after the assistant reply timed out.
- React.js run scaffolded the default Vite app, then ended with `transport_error` after the assistant reply timed out.
- Nuxt.js run repeatedly attempted a blocked `npx nuxi@latest init ...` command and did not reach implementation.

Generated source for the completed failing processes still contained scaffold placeholder UI rather than the requested apps.

## Cause

The deterministic empty-workspace fallback was limited to game/playable requests. General interactive app requests such as task managers, support boards, and CRMs were not classified as quality-gated UI work, so scaffold-placeholder output remained dependent on the model finishing several follow-up edits.

## Fix Direction

- Broaden interactive UI quality detection from game-only requests to structural UI feature requests.
- Materialize a generic runnable management UI fallback for scaffolded Next.js, React/Vite, and Nuxt workspaces.
- Avoid app-domain-specific branching for task board / inquiry board / CRM. The fallback provides a single reusable UI with add, toggle, filter, count, search, status, priority, selected detail, memo, validation, empty state, error feedback, and keyboard handling.
- Keep framework handling limited to file layout and dev-script differences.

## Verification

- `cargo test quality::tests`
