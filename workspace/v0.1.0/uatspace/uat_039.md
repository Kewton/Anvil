## 事象
- `qwen3.5:122b` で `uat_039` を実施したところ、empty workspace から scaffold は成功し、`src/app/page.tsx` の `Read` までは進んだ。
- その次の focused turn で `Edit` が出ず、`thinking...` が 140 秒超まで継続したため手動停止した。

## 問題箇所
- `src/agent/loop_run/turn.rs`
- focused edit 後の assistant timeout / retry 制御

## 根本原因
- `Read` 済み focused edit turn でも、generic な transport retry と chat retry がそのまま有効だった。
- そのため `qwen3.5:122b` が `Edit` を返せないケースで、runtime が長時間 spinner を継続し、UAT 上は停止に見えた。

## 対策
- `Read` 済み focused edit turn には短い hard timeout を適用する。
- さらに generic な transport retry ではなく、focused edit 専用 retry note に切り替えて silent retry を減らす。

## 対策案詳細（仕様）
- `focused_edit_target_already_read(...) == true` の non-streaming reply には専用 timeout override を使う。
- 同条件の timeout 時は `focused_edit_timeout_recovery_note(...)` を追加して 1 回だけ再試行し、それでも timeout なら即座に失敗として返す。
