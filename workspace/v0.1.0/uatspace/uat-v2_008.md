## Cause

The previous exact-anchor recovery fixed the first two post-scaffold edits by replacing the full latest `Read` history with a compact synthetic `Read` for the `<h1>` and `<p>` blocks.

After those two edits, the model read `src/app/page.tsx` again. A later forced focused-edit recovery no longer had a special exact anchor, so the request history again included the full latest `Read`. The model copied nearly the whole file into `old_string`, hit the focused-edit `num_predict=320` cap, and emitted a truncated XML tool call.

## Fix

`src/agent/loop_run/turn.rs` now also uses a compact recovery anchor after any recent truncated tool call when the focused target has already been read and no stronger h1/p exact anchor applies.

The compact anchor is selected from the latest numbered `Read` output, preferring common placeholder CTA text such as `Deploy Now` / `Documentation`, then compact JSX element lines, then a short non-import fallback line. The request history is then rebuilt with the existing synthetic compact `Read`, preventing the model from seeing and copying the full file into `old_string` during forced small-edit recovery.
