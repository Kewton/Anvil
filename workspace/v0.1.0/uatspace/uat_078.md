## Symptom

The run scaffolded a Next.js app and completed the deterministic first small edit in `app/page.tsx`, replacing the default intro text with the `VOID RAIDERS` teaser. After that, the model repeatedly replied without a valid tool call during focused edit continuation. The loop exited with `missing_repo_edits` before applying the deterministic playable page completion.

## Root Cause

The deterministic completion fallback existed for blocked tool turns and future-work prose after a repo edit, but the earlier `requires_action && tool_calls_made_this_turn == 0` branch handled prose-only replies first. Once the teaser edit had landed, a prose-only continuation consumed retry budget instead of checking whether the target page could be completed deterministically.

The same gap existed for empty replies after the teaser edit.

## Fix

`src/agent/loop_run/turn.rs` now checks for a focused page target with `VOID RAIDERS` already present before consuming retry budget in both empty-reply and prose-only no-tool repo-change branches. When present, it applies `deterministic_page_completion_edit_reply`, records a focused edit fallback event, and exits `Done` if the edit succeeds.
