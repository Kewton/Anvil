## 事象
- `anvildev -m qwen3.5:122b -y --sidecar-model qwen3.5:9b --auto-plan` で `sandbox_0424/uat_004` を対象に UAT を実施したところ、Act mode で `create-next-app` による初期 scaffold が失敗した。
- セッションログでは `The directory uat_004 contains files that could conflict: .anvil/` が返っており、その後 `Glob/Read/Bash blocked` を繰り返して停止した。

## 問題箇所
- `src/lib.rs`
  - 起動時に `symlink_anvil_dirs(&config.cwd, &state_root, &session_id)` を無条件で呼び、作業ディレクトリ直下に `.anvil/` を自動生成している。
- `create-next-app .` を含む scaffold フロー
  - 空ディレクトリ前提の scaffold と、作業ディレクトリ汚染が衝突している。

## 根本原因
- runtime state の実体は `state_root/sessions/...` にあるにもかかわらず、CLI 起動時に作業ディレクトリ直下へ `.anvil/` を自動生成して symlink を置いている。
- `create-next-app@latest .` は hidden directory を含む既存ファイルがあると停止するため、Anvil 自身が作った `.anvil/` が scaffold の阻害要因になった。
- 失敗後の Act mode は scaffold 失敗を自律復旧できず、低価値な探索と再試行に入って停止したように見えた。

## 対策案
- `.anvil/` は設定ディレクトリとしてのみ扱い、CLI 起動時には自動生成しない。
- runtime artifact は既存どおり `state_root/sessions/...` を正とし、ユーザーが `.anvil/` を明示的に持っている場合だけ互換 symlink を best-effort で作成する。

## 対策案詳細（仕様）
1. `src/lib.rs` の起動処理は、作業ディレクトリに `.anvil/` が既に存在する場合だけ互換 symlink 作成処理を呼ぶ。
2. `.anvil/` が存在しない場合は何も作らず、作業ディレクトリを空のまま保つ。
3. 既存ユーザーが `.anvil/config` を使っているケースは維持する。設定ディレクトリが存在する時だけ `logs` / `sessions` / `plans` symlink を更新する。
4. 回帰防止として、
   - `.anvil/` が存在しない workspace では起動しても新規作成されない
   - `.anvil/` が既に存在する workspace では互換 symlink が作られる
   を unit test で確認する。
