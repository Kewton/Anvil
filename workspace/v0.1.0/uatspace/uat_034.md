## 事象
- `uat_034` でも empty workspace 初動は安定し、scaffold Bash は通った。
- ただし scaffold 後の実装ターンで、model はまず `src/app/page.tsx` を読もうとし、その後 `app/page.tsx` と `package.json` を読む流れに逸れた。
- 期待していた `app/page.tsx` への first `Edit` には入らず、post-scaffold focused edit が still exploratory read に崩れている。

## 問題箇所
- `src/agent/loop_run/turn.rs`

## 根本原因
- focused edit recovery は guidance note と tool set 制限は掛かっているが、scaffold 後 first read 周辺で wrong-path read / extra read を十分強く抑え切れていない。
- 今回は `app/page.tsx` が正解 target なのに、model が `src/app/page.tsx` へ寄り、さらに `package.json` を追加 read する探索経路が残っていた。
- その結果、`Read -> Edit` に収束すべき turn が `Read -> Read -> think` に戻っている。

## 対策
- post-scaffold focused target が存在する turn では、wrong-path `Read` と target 外 `Read` を execution-time policy でより早く reject する。
- 特に `app/page.tsx` / `src/app/page.tsx` の二択揺れと、`package.json` への exploratory read を first edit 前に止める方向で締める。

## 期待効果
- scaffold 後の first implementation turn が `target read 1 回まで` に収まりやすくなる。
- `uat_034` 型の `wrong-path read -> extra read -> no edit` を減らし、first `Edit` へ押し戻せる。
