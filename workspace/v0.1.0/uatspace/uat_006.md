## 事象
- `sandbox_0424/uat_006` で UAT を実施したところ、classifier fallback 後に Plan mode へ入ったが、最初の plan 生成で 3 分以上 tool call が返らなかった。
- セッションログでは `ollama.chat.request` が `model=qwen3.5:122b` で発行された後、`ollama.chat.response_raw` も tool result も出なかった。

## 問題箇所
- `src/ollama/transport.rs`
  - `should_use_native_tool_calls("qwen3.5:122b") == true` になっており、qwen3.5:122b が native `/api/chat` tool path に入る。
- Plan mode 全般
  - qwen3.5:122b では native tool path の first action が返らず、長時間 spinner のみが続く。

## 根本原因
- qwen3.5:122b の native tool calling は小さな E2E では動いても、今回の Plan prompt では `/api/chat` が実用的な時間で応答しなかった。
- allowlist が広すぎて、安定確認が十分でないモデルまで native tool path に乗せていた。

## 対策案
- qwen3.5:122b を native tool allowlist から外し、`generate/tagged-xml` の既存経路に戻す。
- native tool allowlist は実運用で十分に安定したモデルだけに限定する。

## 対策案詳細（仕様）
1. `should_use_native_tool_calls` は `qwen3.6:27b-coding-nvfp4` のみ true にする。
2. `qwen3.5:122b` は `/api/generate` ベースの tagged-xml tool path を使う。
3. 回帰防止として、allowlist 判定の unit test を追加する。
