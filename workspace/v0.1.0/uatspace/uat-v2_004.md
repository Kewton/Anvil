## Cause

The XML fallback parser rejected the whole tool call when the only malformed portion was a terminal bracket swap: the object had one unmatched `{` and one unmatched `]`. This is a common local-LLM formatting slip under a tight focused-edit prompt and `num_predict=320`.

## Fix

`src/ollama/xml_fallback.rs` now repairs only a narrow terminal bracket swap before rejecting relaxed JSON:

- `{...}]` with one missing object close and one extra array close is parsed as `{...}}`
- `[...]}` with one missing array close and one extra object close is parsed as `[...]`
- repairs are skipped while inside an unterminated JSON string

Added a regression test for the exact `Edit` tool-call shape seen in this run.
