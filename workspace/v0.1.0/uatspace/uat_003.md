# 事象
- `uat_003` の E2E で、Plan mode は approval prompt まで正常に到達したが、`yes` 後の Act mode で `package.json` 作成直後に進行が止まったように見えた。
- terminal には footer の再描画だけが続き、その後の tool call や最終応答が返ってこなかった。

# 問題箇所
- [src/agent/loop_run/lifecycle.rs](/Users/maenokota/share/work/github_kewton/Anvil-develop/src/agent/loop_run/lifecycle.rs)
- [src/ollama/client.rs](/Users/maenokota/share/work/github_kewton/Anvil-develop/src/ollama/client.rs)

# 根本原因
- Act mode の最初の repo edit 後、late-turn compaction が発火して sidecar (`qwen3.5:9b`) に conversation summary を同期リクエストしていた。
- `summarize_conversation()` は通常の Ollama client timeout（120 秒）を使うため、sidecar が詰まると compaction 全体が長時間 block される。
- runtime は sidecar summary 完了まで次の tool loop に進めないため、ユーザーには「package.json を書いたあと停止した」ように見える。

# 対策案
- sidecar summary は短い専用 timeout で実行し、失敗・タイムアウト時は即座に local compaction にフォールバックする。
- summary 用の `num_predict` も小さくして、sidecar が返すまでの待ち時間を抑える。

# 対策案詳細（仕様）
- `summarize_conversation()` は通常の `self.http` を使わず、summary 専用の短い timeout client を使う。
- timeout の目安は 8 秒前後とし、summary の `max_predict` は 384 程度まで落とす。
- sidecar summary が
  - timeout
  - transport error
  - empty summary
  - unexpected tool call
  のいずれでも失敗した場合、`compact_messages()` へ即フォールバックする。
- 回帰確認:
  - `cargo build --release`
  - UAT を再実行し、Act mode の最初の repo edit 後に footer 再描画だけで固まらず、次の tool call へ進むことを確認する
