## 事象
- `uat_016` で classifier fallback は効いたが、Plan Stage 1 で `qwen3.5:122b` が `Goal/Constraints/Deliverables` だけでなく `Acceptance Criteria` 以降まで含む巨大な `Write` を出した。
- その最初の `Write` は parse error (`unterminated <anvil_tool_call> block`) で落ち、その後 repo root に対する `Read('.')` に逃げた。
- 続く `Write` では plan file に全セクションを書き込んだが、Stage 2 で `Quality Bar` が repo-specific でないため incomplete 判定に戻された。

## 問題箇所
- `src/tools/registry.rs`
- `src/agent/loop_run/turn.rs`

## 根本原因
- Plan mode では「plan file 以外を書かせない」制約はあるが、「現在 stage で許可されていない section を plan file に書かせない」制約が無い。
- そのためモデルが Stage 1 で後続 section まで一気に書いても runtime は受理してしまい、stage discipline が prompt 依存になっている。
- `qwen3.5:122b` はこの依頼で大きい plan `Write` を出しやすく、parse failure 後も broad な `Read('.')` に流れやすい。

## 対策案
- tool registry で plan file `Write/Edit` に stage-scope guard を入れ、現在 stage で許可されていない `## Section` 見出しを含む更新を reject する。
- Stage 1 は `Goal/Constraints/Deliverables` のみ、Stage 2 は `Acceptance Criteria/Quality Bar` のみ、Stage 3 は `Execution Plan/Verification Plan/Risks / Fallbacks` のみ許可する。

## 対策案詳細（仕様）
1. `ToolContext` に `plan_stage` を持たせる。
2. `src/tools/registry.rs` の `Write/Edit` 実行前に、plan file 向け更新の payload を見て `## <section>` 見出しを検査する。
3. current stage で未許可の section を含む場合は tool error を返し、later section 名をエラーメッセージに含める。
4. unit test
   - Stage 1 で `Acceptance Criteria` を含む `Write` が reject されること
   - Stage 2 で `Acceptance Criteria` と `Quality Bar` だけの `Edit` は許可されること
