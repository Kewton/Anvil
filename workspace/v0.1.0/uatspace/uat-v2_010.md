- 事象
  - `uat-v2_010` は `done` で終了したが、生成された `src/app/page.tsx` は Space Invaders ではなかった。
  - 内容は Next.js テンプレートを少し変更しただけで、`Local-First Coding Agent`、`Start Experience`、`Documentation` などの汎用 UI が残り、プレイヤー・敵・弾・スコア・ライフ・ゲームループが存在しなかった。

- 問題箇所
  - `src/agent/loop_run/turn.rs`
  - Act モードの最終回答受理処理。

- 根本原因
  - セッション圧縮後の summary と汎用 plan 文脈により、モデルが「requested experience」を具体的な Space Invaders ではなく、汎用的なインタラクティブデモとして満たしたと誤判定した。
  - ランタイム側は、最終回答前に実装ファイルが要求ドメインと品質バーを満たすかを検査していなかったため、起動確認だけで `done` を受理した。

- 対策案
  - Act モードで repo change が期待されるゲーム/UIタスクについて、最終回答を受理する前に実装品質ゲートを実行する。
  - 実装ファイルに要求されたゲームドメイン（例: Space Invaders / Breakout / Tetris）や基本ゲーム要素（player/enemy/bullet/score/input/state 等）が不足している場合、`done` を認めず、元のユーザー要求を明示した system note を追加して実装を継続させる。

- 対策案詳細（仕様）
  - `request_needs_playable_ui_quality_gate` でゲーム系アプリ要求を判定する。
  - `implementation_quality_issue_for_request` で、要求ドメイン不一致、ゲームメカニクス不足、テンプレート/汎用 placeholder の残存を検出する。
  - 最終回答受理直前に `accepted_repo_change_quality_issue` を呼び、問題があれば `repo_change_quality_gate_note` を push して継続する。
  - Space Invaders の汎用 placeholder を拒否し、最低限の Space Invaders 実装断片は受理するユニットテストを追加する。
