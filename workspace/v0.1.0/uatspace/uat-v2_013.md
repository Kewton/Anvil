- 事象
  - `uat-v2_013` は `done` で正常終了扱いになったが、生成物は要求されたスペースインベーダーゲームではなかった。
  - `src/app/page.tsx` は scaffold の placeholder が残り、見出しだけ `Local-First Coding Agent` に変更された状態だった。
  - `next.svg`、`vercel.svg`、`Documentation`、`Templates` などの scaffold 要素も残っていた。

- 問題箇所
  - `src/agent/loop_run/turn.rs`
    - final 前の repo change quality gate 条件
    - `accepted_repo_change_quality_issue`

- 根本原因
  - auto-plan 実行では、ユーザーの元の開発要求は working memory の active task に保持される。
  - しかし plan 承認後の Act loop の直近入力は `yes` であり、`classify_action_expectation(input, Act)` は RepoChange にならない。
  - final 前の品質ゲートが直近入力の action expectation だけを見ていたため、active task が明確に repo change を要求していても quality gate が実行されなかった。

- 対策案
  - final 前の repo change quality gate は、直近入力が RepoChange の場合だけでなく、active task が RepoChange を要求している場合にも適用する。
  - plan 承認の `yes` は実装要求を取り消す入力ではないため、active task を品質判定の主入力として扱う。

- 対策案詳細（仕様）
  - `should_apply_repo_change_quality_gate(action_expectation, active_task_expects_repo_change, mode)` を追加する。
  - Act mode かつ `action_expectation == RepoChange || active_task_expects_repo_change` の場合に quality gate を適用する。
  - Plan mode では適用しない。
  - テストで `yes` 相当の `ActionExpectation::None` でも active task が repo change なら gate 対象になることを確認する。
