## 事象
- `uat_035` では empty workspace からの scaffold は安定し、post-scaffold の first read は `app/page.tsx` に正しく着地した。
- 一方で同一 assistant 応答内に `Read app/page.tsx` の後で `Glob *` が混ざり、first `Edit` へ進まず長考の末に no-edit retry へ落ちた。

## 問題箇所
- `src/agent/prompting.rs`
- `src/system_prompt.rs`
- `src/agent/loop_run/turn.rs`

## 根本原因
- `src/app/page.tsx` 固定の prompt バイアスは今回の修正で解消できたが、focused edit recovery 中でも 1 応答に複数 tool call を含む返答を許していた。
- そのため `Read target -> exploratory Glob` のような batch が入り込み、exactly-one-tool-call 方針と実行時の収束がずれていた。

## 対策
- Next.js 既定パスの文言を `app/page.tsx` / `src/app/page.tsx` の実レイアウト追従へ修正した。
- focused edit recovery 中の tool batch を runtime で検査し、単一 focused action に絞る方向へ強化する。

## 期待効果
- scaffold 後の first implementation turn で `src/app/page.tsx` への誤誘導を減らせる。
- `Read -> Glob -> no edit` のような exploratory batch を抑え、first `Edit` へ近づける。
