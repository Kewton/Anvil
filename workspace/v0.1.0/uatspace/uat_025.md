## 事象
- `uat_025` で `anvildev -m qwen3.6:27b-coding-nvfp4 -y --sidecar-model qwen3.5:9b --auto-plan` を `/Users/maenokota/share/work/localwork/codextest/sandbox_0424/uat_025` で実行したところ、21 秒で `missing_repo_edits` により終了した。
- `space-invaders` の Next.js scaffold 自体は生成されたが、`app/page.tsx` などの実装 edit には到達せず、最後は `Read("space-invaders")` でディレクトリ一覧を読んだだけで停止した。
- `llm-io.jsonl` と `session.json` を確認すると、初手の scaffold Bash は `npx create-next-app@latest space-invaders ... 2>&1 | tail -20` だったが、runtime 正規化で `--yes` がパイプ末尾側へ入り、`tail: unrecognized option '--yes'` を起こしていた。

## 問題箇所
- `src/tools/bash.rs`
- `src/agent/loop_run/turn.rs`
- `src/agent/prompting.rs`

## 根本原因
- `normalize_noninteractive_scaffold_command` が shell command 全体の末尾へ `--yes` / `--use-npm` を付与しており、`create-next-app ... | tail -20` のようなパイプ付き command では `tail --yes` に壊れていた。
- scaffold 後の focused recovery は `app/page.tsx` / `src/app/page.tsx` を現 work root 直下でしか探しておらず、`space-invaders/app/page.tsx` のような「scaffold で作られたサブディレクトリ型プロジェクト」を対象化できなかった。
- その結果、runtime が「具体的な実装ファイル」ではなくディレクトリ read を許してしまい、モデルが実 edit へ遷移しないまま `missing_repo_edits` に落ちた。

## 対策案
- scaffold command 正規化を shell segment 単位にし、`create-next-app` invocation の引数部分だけへ `--yes` / package manager flag を差し込む。
- scaffold 後 recovery の target 解決を拡張し、work root 直下だけでなく「直接子ディレクトリに作られた Next.js/React 系 scaffold」の `app/page.tsx` / `src/app/page.tsx` も優先候補に含める。
- 併せて回帰テストを追加し、`| tail -20` 付き scaffold command と nested project recovery を自動で守る。

## 対策案詳細（仕様）
- `src/tools/bash.rs`
  - scaffold command を shell control operator ごとに分割し、`create-next-app` を含む segment のみを正規化する。
  - segment 内では trailing redirection (`2>&1`, `>file`, `<file`) を保護し、flags は redirection の前へ挿入する。
  - 既に `--yes` / `-y` / package manager flag がある場合は重複追加しない。
- `src/agent/loop_run/turn.rs`
  - `first_existing_impl_target` を拡張し、work root 直下に加えて direct child project root (`package.json` または `next.config.*` を持つディレクトリ) を探索対象にする。
  - page component を最優先し、`app/page.tsx` / `src/app/page.tsx` を見つけたら focused recovery target として返す。
  - nested target の場合でも first-slice note が効くよう、`app/page.tsx` suffix 判定で static game shell note を出す。
- 検証
  - unit test: `create-next-app ... 2>&1 | tail -20` で `--yes` が `tail` 側へ入らないこと
  - unit test: nested scaffold (`space-invaders/app/page.tsx`) を `first_existing_impl_target` が返すこと
  - `cargo test` と `cargo build --release` 後に `uat_026` から再実施する
