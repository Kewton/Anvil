- 事象
  - Scenario 03 / qwen3.5 の4手目で、既存 React UI に対して「月別サマリー」と「入力ミスを防ぐバリデーション」を追加する指示を実行したが、対象ファイルに `monthlySummary`、月別表示、追加の検証ロジックが入らなかった。
  - 実行が長時間継続したため中断し、失敗扱いとした。
- 問題箇所
  - `src/agent/loop_run/quality.rs`
  - 既存実装改善時の deterministic polish fallback が、見た目改善やゲームUI改善に寄っており、業務UIの「集計」「検証」のような意味的改善を補完できなかった。
- 根本原因
  - 非ゲームUIの初期生成は安定化していたが、既存コード改善フェーズでは、モデルが編集を試みた後に意味的な改善が不足していても、汎用的に補正する経路がなかった。
  - 「1つ目の...追加して下さい」のような改善指示を、改善操作として扱う判定も不足していた。
- 対策案
  - 特定ドメイン名ではなく、`summary` / `monthly` / `validation` / `サマリー` / `月別` / `バリデーション` / `入力ミス` などの汎用的な改善要求語を検出する。
  - 既存コードが Anvil の汎用業務UIテンプレート由来と判断できる場合に限り、画面構成を保ったまま月別サマリーと入力検証を追加する deterministic polish fallback を適用する。
  - 任意の既存アプリを全面置換しないよう、`Operations Board` / `Work Queue` / `addMemo` などのテンプレート由来マーカーが揃う場合だけ対象にする。
- 対策案詳細（仕様）
  - 改善判定に、既存対象を示す `既存`、および `1つ目` 等と `追加` の組み合わせを追加する。
  - React テンプレート改善では、`month` フィールド、`monthlySummary` 集計、`Monthly Summary` セクション、`validateTaskTitle`、短すぎる入力と重複入力のエラー表示を追加する。
  - Vue テンプレート改善にも同等の月別集計と入力検証を追加する。
  - 回帰テストとして、月別サマリーと入力検証の改善指示で `data-anvil-polish="v1"`、`monthlySummary`、`validateTaskTitle` が生成され、既存の主要構造が残ることを確認する。
