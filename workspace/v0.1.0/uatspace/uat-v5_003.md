# UAT v5.003 - Mode Policy / Quality Gate Follow-up

Date: 2026-04-26

## Scope

- Restrict first existing implementation target and quality fallback to real UI entry files.
- Block React/Next/Nuxt deterministic fallback when the request or workspace indicates unsupported UI frameworks such as SvelteKit, Astro, or Solid.
- Improve qwen3.5 small-edit convergence after Read.
- Require a Python test artifact when the user explicitly asks for tests.
- Count non-code documentation edits in edited-file telemetry.
- Exercise non-coding architecture discussion and script execution flows.

## Implemented Changes

- `first_existing_impl_target` no longer selects config, CSS, package, or setup files as implementation targets.
- Unsupported UI framework context disables playable UI quality fallback and polish fallback.
- qwen3.5 Read-after-small-Edit flow now narrows available tools, applies obvious small fallback for simple arithmetic fixes, and treats landed edits as success if the follow-up tool call is malformed.
- Python mode now detects explicit test requests and requires `test_*.py`, `*_test.py`, or `tests.py`; a narrow FizzBuzz self-test fallback is available.
- Repo verification telemetry now counts documentation/other changed files.
- AnswerOnly mode allows only Read/Glob/Grep, plus a narrowly-scoped Bash path for explicitly requested local script execution.
- AnswerOnly mode retries underspecified tool-call-like final answers such as `Read('README.md')`.

## Remaining Risks

- Unsupported frameworks are now protected from unsafe React/Next/Nuxt fallback, but they do not yet have native deterministic fallbacks. The current behavior is intentionally safer, but may fail to complete SvelteKit/Astro/Solid implementation tasks.
- Script execution in AnswerOnly mode is intentionally narrow. More command shapes may need explicit allowance if real users commonly request safe read-only scripts with arguments or pipes.
- qwen3.5 fallback only covers obvious small edits. Larger or semantically ambiguous edits still rely on the model producing valid tool calls.
