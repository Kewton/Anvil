## 事象
- `uat_042` の対策として、scaffold 直後の note を「返ってきた `<main>...</main>` ブロックだけ置換する」に絞って `uat_043` を実施した。
- それでも scaffold と `Read src/app/page.tsx` の後、`tool call parser failed: truncated tool call (generate response hit length limit)` で終了した。

## 問題箇所
- `src/agent/recovery.rs`
- scaffold 後 first `Edit` 向け focused recovery note

## 根本原因
- `<main>...</main>` 全体でも、default Next page では依然として `old_string` anchor が広すぎる。
- そのため model は page の主要部分をまとめて差し替えようとし、compact `Edit` 1 件に収まらない。

## 対策
- `<main>` 全体ではなく、その内部の central marketing copy block だけを対象にする。
- first `Edit` note に start marker を具体的に書き、置換範囲の曖昧さを減らす。

## 対策案詳細（仕様）
- `app/page.tsx` / `src/app/page.tsx` 向け note では、`<div className="flex flex-col items-center gap-6 text-center sm:items-start sm:text-left">` から対応する `</div>` までだけを `old_string` anchor にする。
- imports と component signature はそのまま維持し、返す `Edit` は 1 contiguous block のみに制限する。
