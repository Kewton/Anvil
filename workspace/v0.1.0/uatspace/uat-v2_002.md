# uat-v2_002

## 事象

- `uat-v2_001` の focused edit 修正後、同じ Space Invaders UAT を再実行。
- scaffold と `src/app/page.tsx` の Read までは進んだ。
- focused edit recovery で `Edit` のみを要求した後、`tool_call_format_error` で停止。

```text
tool call parser failed: truncated tool call (generate response hit length limit)
```

## 問題箇所

- `first_scaffold_shell_edit_exact_anchor_note` が、既読の Next.js 初期ページから `<h1>` から `</p>` までの長い JSX ブロックを `old_string` として丸ごと要求していた。
- focused edit recovery は `num_predict=320` に制限されるため、`old_string` だけで出力予算の大半を消費し、`new_string` と XML/JSON wrapper が閉じる前に生成上限へ到達した。

## 根本原因

- 「小さい Edit を強制する」ための recovery note が、実際には巨大な `old_string` をモデルに出させていた。
- ツールを `Edit` に絞るだけでは不十分で、`Edit` の JSON 自体が短く完結できるアンカー設計になっていなかった。

## 対策

- scaffold 後の最初の focused edit では、長い intro copy 全体ではなく `<h1>` 見出しブロックだけを exact anchor にする。
- 初回 Edit は見出し差し替えだけに限定し、後続の continuation edit で段階的に UI とロジックを拡張させる。
- これにより `old_string` / `new_string` / wrapper を `num_predict=320` 内に収めやすくし、モデルの長文生成や truncate に依存しない。
