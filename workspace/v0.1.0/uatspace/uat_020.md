## 事象
- `uat_019` の Plan mode で Stage2 編集後に `Read` が失敗し、モデルが再び plan file path の扱いで混乱した。
- 具体的には、`Write/Edit` は active plan file に正規化されて成功する一方で、`Read /Users/.../sandbox_0424/uat_019/plans/plan-....md` は `No such file or directory` で失敗した。
- その結果、モデルが「plan file は project root 外にある」と再解釈し、plan completion が止まった。

## 問題箇所
- `src/tools/registry.rs`

## 根本原因
- plan file alias 正規化は `Write` / `Edit` の path 解決には入っているが、`Read` には入っていない。
- そのため、モデルが `plans/plan-...` の相対 alias や、`<work_root>/plans/plan-...` の絶対 alias を使うと、書き込みは active plan file に届く一方、読み込みだけは実在しない sandbox path を見に行って失敗する。
- tool ごとに alias の意味が変わるため、モデル視点では plan file の所在が不安定に見える。

## 対策案
- Plan mode の `Read` でも active plan file alias を `Write` / `Edit` と同じ規則で正規化する。
- `plans/<filename>`、basename、同一 filename の absolute alias はすべて active plan file として扱う。

## 対策案詳細（仕様）
- `ToolRegistry::execute("Read", ...)` の path 解決時に、まず active plan file alias への正規化を試す
- alias が active plan file と一致する場合は、実際の read 対象を session state 配下の active plan file に置き換える
- 一致しない path だけ通常の `resolve_user_path` で解決する
- 期待結果:
  - plan file の `Read/Write/Edit` で同じ alias 規則が使われる
  - Stage2/Stage3 中に `failed to stat ... sandbox_0424/.../plans/plan-...` が出なくなる
  - plan file path 誤認による stall が減る
