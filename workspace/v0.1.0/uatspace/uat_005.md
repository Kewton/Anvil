## 事象
- `sandbox_0424/uat_005` で UAT を実施したところ、ユーザープロンプト投入後 2 分以上 UI が進まず、Plan mode にも Act 実行にも入らなかった。
- セッションログには `ollama.generate.request` が 1 件だけ残り、その後 `response_raw` も `classifier.result` も出なかった。

## 問題箇所
- `src/agent/loop_run/commands.rs`
  - `classify_large_task_with_main_model` が auto-plan classifier を main model に同期で投げている。
- `src/ollama/client.rs`
  - classifier 用の短時間・小出力リクエスト経路がなく、通常の `chat_text` と同じ `num_predict=2048` / 長い HTTP timeout に依存している。

## 根本原因
- `--auto-plan` の最初の分類が `qwen3.5:122b` を使った重い同期 generate 呼び出しになっており、分類用途としては過剰だった。
- classifier が返らない間は fallback が発動せず、UI にも進捗が出ないため、ユーザーからは「途中で停止した」ように見えた。

## 対策案
- auto-plan classifier は sidecar model がある場合は sidecar を優先して使う。
- classifier 専用に短い timeout と小さい `num_predict` を持つ経路を用意し、一定時間で失敗扱いにして heuristic fallback に落とす。

## 対策案詳細（仕様）
1. classifier の使用モデルは `sidecar > main` の順で選ぶ。
2. classifier 用 Ollama client は通常チャットとは別に `timeout=20s`、`num_predict=160` 程度の軽量設定を使う。
3. classifier のログには実際に使った model 名を出す。
4. classifier が timeout / transport error なら既存の heuristic fallback を使って Plan/Act を継続する。
5. 回帰防止として、
   - classifier model 選択の unit test
   - transport error 判定の既存 test 維持
   を確認する。
