- 事象
  - `uat_055` で `anvildev -m qwen3.5:122b -y --sidecar-model qwen3.5:9b --auto-plan` を実行したところ、Plan mode の iter 2 で `qwen3.5:122b` が 170 秒以上 `thinking...` のまま停止した。
  - ESC interrupt 後も `stopping after current operation` となり、Ollama 呼び出し完了まで戻らなかったため、該当 `anvildev` プロセスを停止した。
  - リポジトリ編集は 0 件で、Next.js アプリ生成には進まなかった。

- 問題箇所
  - `src/agent/loop_run/turn.rs`
  - `should_use_streaming_transport`
  - `non_streaming_assistant_reply_timeout_secs`

- 根本原因
  - `qwen3.5:*` は native tools 有効時に streaming transport を使う判定になっていた。
  - 90 秒 hard timeout は non-streaming path の `recv_timeout` にのみ実装されているため、streaming path では長時間応答しない Ollama 呼び出しを境界で止められない。
  - interrupt は現在の LLM operation 完了後に効く設計のため、streaming request が返らない場合は停止できない。

- 対策案
  - `qwen3.5:*` は native tools 有効/無効に関わらず non-streaming transport を使う。
  - これにより既存の 90 秒 timeout、sidecar fallback、deterministic fallback plan materialization の経路へ必ず入るようにする。

- 対策案詳細（仕様）
  - `should_use_streaming_transport` で `is_qwen35_family(model)` の場合は常に `false` を返す。
  - `non_streaming_assistant_reply_timeout_secs` も `qwen3.5:*` の場合は native tools 状態に依存せず 90 秒を返す。
  - 既存の qwen3.5 non-streaming timeout テストを native tools 有効ケースまで拡張し、streaming 判定テストを更新する。
