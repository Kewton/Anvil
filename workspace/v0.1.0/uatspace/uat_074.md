## Symptom

The run failed with `missing_repo_edits` after the focused edit fallback had already written a playable `app/page.tsx`.

The terminal showed both deterministic fallback paths:

- `Model answered without tools after reading the target; applying deterministic...`
- `Small scaffold edit stalled in prose; applying deterministic playable page completion.`

After that, the loop still emitted repeated `Retry requested` notes and exited:

```text
✘ missing_repo_edits  iter 7/50  duration 150s  edited 12 files
assistant kept stopping before making the requested repository edits
```

## Root Cause

The deterministic completion fallback successfully executed its `Edit` tool call, but the control flow used `continue` unconditionally afterward. This returned to the LLM loop instead of accepting the deterministic playable page as the completed Act result.

Because the next model turns were still future-work prose, the existing partial-progress retry guard counted them and eventually returned `missing_repo_edits`, even though the repository already contained a good playable implementation.

## Fix

When `deterministic_page_completion_edit_reply` is used after a prose stall:

- Execute the fallback tool call as before.
- Detect tool errors from the raw tool result.
- If the fallback edit succeeds, set a completion summary, mark `ExitReason::Done`, and break the outer loop.
- Only continue the retry path if the fallback tool call failed.
