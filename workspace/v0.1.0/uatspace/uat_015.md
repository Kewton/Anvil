## 事象
- `uat_015` で Plan は完了し、Act でも `create-next-app` までは成功した。
- その後 `qwen3.5:122b` は `npm run dev -- -p 3011` を前景実行し、Next.js は `http://localhost:3011` で `Ready` になったが、Bash tool は 15 秒 timeout で child を kill した。
- timeout 後の次ターンで巨大な `Write` が再び発生し、`done_reason=length` で tool call が途中切れになった。

## 問題箇所
- `src/tools/bash.rs`
- `src/agent/loop_run/turn.rs`
- `src/agent/recovery.rs`

## 根本原因
- `npm run dev` 系の長時間常駐コマンドを、末尾に `&` がない限り前景のまま実行していた。
- そのため、サーバーが正常に起動していても 15 秒 timeout 到達時に runtime が kill してしまい、Act が「起動成功後の実装」に進みにくい。
- さらに、Act で Bash だけが続いたターンの後に `Read -> small Edit` へ寄せる矯正が弱く、`qwen3.5:122b` が再び大きい full-file `Write` を出しやすい。

## 対策案
- `npm run dev`, `next dev`, `vite` など常駐 dev server コマンドは、末尾 `&` がなくても runtime 側で自動的に detached background 実行へ正規化する。
- Act で repo edit がまだ 0 件なのに Bash だけ実行したターンの直後は、次ターンで `Read` の後に `small Edit` を行う recovery note を必ず差し込む。

## 対策案詳細（仕様）
1. `src/tools/bash.rs`
   - `npm run dev`, `next dev`, `vite`, `python -m http.server` など persistent service 起動コマンドを判定する。
   - それらは `nohup sh -lc ... >log 2>&1 </dev/null &` 形式へ自動変換し、`background_pid=` と `background_log=` を返す。
   - 既存の明示 `&` 付き background 実行と同じ出力形式に揃える。
2. `src/agent/loop_run/turn.rs`
   - Act mode で、そのターンの tool が Bash のみかつ repo edit がまだ 1 件もない場合、次ターンの前に recovery note を追加する。
3. `src/agent/recovery.rs`
   - 新しい note は「setup/verification は終わったので、次は `Read` してから `small Edit`」を明示し、追加の scaffold/dev-server 実行を止める。
4. test
   - foreground `npm run dev -- -p 3011` が自動的に detached command へ変換されること。
   - setup 後 recovery note が `Read` と `small Edit` を要求すること。
