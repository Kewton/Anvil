# 事象
- `uat_002` の E2E で、Plan mode 中に `Read -> Write -> Read -> Write` の途中で停止したように見え、2分以上 approval prompt まで戻らなかった。
- ログには plan file への `Write` が続いているように見えるが、実際の session plan file には Stage1 相当しか反映されておらず、`Acceptance Criteria` 以降が未記入のままだった。

- [src/agent/loop_run/turn.rs](/Users/maenokota/share/work/github_kewton/Anvil-develop/src/agent/loop_run/turn.rs)
- [src/agent/loop_run/lifecycle.rs](/Users/maenokota/share/work/github_kewton/Anvil-develop/src/agent/loop_run/lifecycle.rs)

# 根本原因
- Plan mode でモデルが `plan-1776960363.md` や作業ディレクトリ配下の同名 path を指定すると、runtime は active plan file と一致しないとして reject するケースが残っていた。
- 一方で progress 表示側はそれを plan write に近い形で見せるため、ユーザーには「plan が進んでいる」ように見えるが、実体の active plan file は更新されないことがあった。
- さらに plan mode 中でも late-turn compaction が発火し、sidecar summary を同期的に待つため、plan 未完了のまま compaction 待ちで停止して見えるケースがあった。

# 対策案
- Plan mode の write target 解決で、active plan file と同じ basename の path を active plan file に正規化する。
- 自動 compaction は Act mode のみで行い、Plan mode 中は compaction を走らせない。
- これにより、plan の書き込み先と progress 表示の判定を一致させ、plan approval 前に sidecar summary 待ちで固まる経路を塞ぐ。

# 対策案詳細（仕様）
- `resolve_plan_mode_write_target()` で以下を active plan file alias として受理する。
  - `plans/plan-xxxx.md`
  - `plan-xxxx.md`
  - 作業ディレクトリ配下または絶対 path で指定された同名 `plan-xxxx.md`
- 上記 path は実行時にすべて active plan file へ正規化して `Write/Edit` を実行する。
- `run_turn()` 冒頭の通常 compaction と tool loop 後の late-turn compaction は、Plan mode 中は skip する。
- 回帰確認:
  - unit test で basename alias と absolute alias を受理することを確認する
  - UAT を再実行し、Plan mode が approval prompt まで到達することを確認する
