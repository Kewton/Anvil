# UAT v3 品質評価シナリオ

## 目的

`workspace/v0.1.0/uatspace/v2/uatplan_v2.md` のE2E手法を踏襲しつつ、異なる品質観点を広く評価するためのシナリオ集です。

各シナリオは4つの指示で構成します。各指示は新しいセッションで実行し、同一シナリオ内では指定された作業ディレクトリ配下を使います。途中で `yes` が必要な場合は `yes` を返して先へ進みます。

## 共通実行条件

- 作業ルート: `/Users/maenokota/share/work/localwork/codextest/sandbox_0424`
- 実行ディレクトリ: `uat-v3_NNN/scenario_XX/instruction_Y`
- 起動ポート: 指示に明記がある場合はそのポートを使う。明記がない場合は `3011`。
- まず `qwen3.5:122b` で3回連続合格まで確認し、その後 `qwen3.6:27b-coding-nvfp4` で3回連続合格まで確認する。
- コマンド:

```sh
anvildev -m qwen3.5:122b -y --sidecar-model qwen3.5:9b --auto-plan --fresh-session
anvildev -m qwen3.6:27b-coding-nvfp4 -y --sidecar-model qwen3.5:9b --auto-plan --fresh-session
```

## 共通合格基準

- 4つの指示すべてで、説明だけではなく実ファイルが生成または更新される。
- `npm install` が必要な生成物では依存関係をインストールできる。
- フロントエンド生成物は指定ポートで `npm run dev -- -p <PORT>` または同等コマンドにより起動できる。
- 主要機能がソースコード上で確認できる。例: state、イベントハンドラ、入力、フィードバック、永続化、エラー表示、テスト、アクセシビリティ属性など。
- 既存アプリ改善指示では、既存機能を壊さず、対象ファイルに意味のある改善が入る。
- 失敗時は `workspace/v0.1.0/uatspace/uat-v3_NNN.md` にインシデントを記録する。

## インシデント記録テンプレート

```md
- 事象
- 問題箇所
- 根本原因
- 対策案
- 対策案詳細（仕様）
```
