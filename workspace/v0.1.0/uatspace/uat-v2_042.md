- 事象
  - qwen3.5:122b の UAT 4 指示は完走したが、2 本目の React/Vite アプリで `npm run dev -- -p 3011` が失敗した。
  - エラーは `CACError: Unknown option '-p'`。

- 問題箇所
  - `src/agent/loop_run/quality.rs`
  - React/Vite 用の deterministic framework game files の `package.json`

- 根本原因
  - UAT手順は全フレームワーク共通で `npm run dev -- -p 3011` を実行する。
  - Next.js と Nuxt は `-p` を受け付けるが、Vite は `--port` を要求し、短縮 `-p` を未知のオプションとして拒否する。
  - 生成された React/Vite の `dev` script は Vite CLI へ追加引数をそのまま渡すため、UAT手順の `-p 3011` を吸収できなかった。

- 対策案
  - React/Vite 生成物には `npm run dev -- -p 3011` と `npm run dev -- --port 3011` の両方を扱える小さな dev wrapper を同梱する。
  - wrapper は追加引数の `-p <port>` を `--port <port>` に正規化し、指定がない場合は要求ポートを既定値として Vite を起動する。

- 対策案詳細（仕様）
  - React deterministic fallback の `package.json` は `"dev": "node scripts/dev.mjs"` とする。
  - `scripts/dev.mjs` は `node:child_process` で `vite --host 0.0.0.0` を起動する。
  - 引数内の `-p <value>` は `--port <value>` に変換する。
  - `--port` / `--port=<value>` が指定されていない場合、要求されたポートを追加する。
  - wrapper は stdout/stderr を継承し、Vite の終了コードをそのまま返す。
