## Failure

Instruction 3 requested a Nuxt.js Tetris app on port 3011. The model entered Act mode, then repeatedly emitted Bash commands beginning with an absolute `cd /Users/maenokota/share/work/localwork/codextest/sandbox_0424/uat-v2_034/instruction_3_tetris ...`.

The runtime blocked these as repeated Bash loop attempts:

```text
Bash loop blocked
Repeated shell command detected; choose a different next step.
```

The workspace stayed empty and no implementation file was created. The recovery note asked the model to inspect or edit files, but that was not actionable in an empty workspace, so the run was interrupted.

## Root Cause

The existing deterministic empty-workspace scaffold fallback only covered Next.js. React and Nuxt requests depended on the model producing a good scaffold command and then recovering from scaffold failures. When the model repeated a scaffold-style Bash command in an empty Nuxt workspace, loop prevention correctly blocked the repetition, but no deterministic fallback existed to materialize the minimal framework files.

## Fix Direction

Add a generic empty-framework game fallback for Next.js, React/Vite, and Nuxt:

- Trigger only for empty workspaces and playable game app requests.
- Materialize the minimal framework files directly instead of retrying network scaffolds.
- Reuse the existing deterministic canvas game templates.
- Preserve the requested dev port in `package.json`.

This keeps the fix generic across supported frontend frameworks and prevents scaffold/recovery loops from blocking playable game requests.
