# uat-v2_038 incident

## Context

- Model: `qwen3.5:122b`
- Sidecar: `qwen3.5:9b`
- Command: `anvildev -m qwen3.5:122b -y --sidecar-model qwen3.5:9b --auto-plan`
- Instruction 1: Next.js space invaders app on port 3011

## Symptom

The deterministic framework game fallback successfully materialized a runnable
Next.js canvas game, but the turn continued into additional LLM calls. The
model read and edited `src/app/page.tsx`, then spent more than three minutes in
another assistant call. ESC only requested interruption after the in-flight
operation, so the UAT run had to be stopped manually.

The generated app already contained the required quality markers:

- `package.json` with `next dev -p 3011`
- `src/app/page.tsx`
- `const MODE = "invaders"`
- `canvas`
- `requestAnimationFrame`
- `keydown`
- `Restart`
- visible title `NEON INVADERS`

## Cause

The fallback path counted as a repo edit but returned to the normal actor loop.
For these deterministic empty/sparse game workspaces, continuing to ask the
model for extra implementation after a complete fallback reintroduced the same
long-running model instability the fallback was meant to avoid.

## Fix

When `maybe_materialize_framework_game_fallback` writes framework game files,
finish the current repo-change turn immediately with `ExitReason::Done`.
