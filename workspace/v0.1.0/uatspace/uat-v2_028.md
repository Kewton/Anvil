# UAT v2 028 incident

- Model: `qwen3.5:122b` with sidecar `qwen3.5:9b`
- Scenario: exact v2 UAT instruction 2, `React.js` ball-breaker game.
- Result: failed quality bar for framework fidelity.

## What Happened

The agent produced a playable breakout canvas game, but it scaffolded with
`create-next-app` and left the project as a Next.js app:

- `package.json` used `next dev`.
- implementation target was `src/app/page.tsx`.
- no Vite/plain React entry such as `src/App.tsx` existed.

The generated UI itself was playable, but instruction 2 explicitly asks for a
React.js app while instruction 1 is the Next.js variant, so accepting this would
hide framework drift in the E2E run.

## Cause

The empty-workspace guidance only forced an explicit framework scaffold for
Next.js requests. For non-Next framework requests, the model only saw generic
"scaffold the minimum project" guidance and could choose `create-next-app`.

## Fix Direction

Make framework fidelity explicit and generic:

- detect explicit `Next.js`, `React.js`, and `Nuxt.js` requests;
- tell the model to scaffold the requested framework in an empty workspace;
- reject first scaffold commands that use a different framework.

This keeps the response framework-agnostic instead of adding prompt-specific
special cases for the current UAT text.
