# UAT v2 029 incident

- Model: `qwen3.5:122b` with sidecar `qwen3.5:9b`
- Scenario: exact v2 UAT instruction 2, `React.js` ball-breaker game.
- Result: failed before completion.

## What Happened

After the framework-fidelity fix from `uat-v2_028`, the agent still attempted a
non-preferred React scaffold:

- `npx create-react-app . --template cra-template --yes`
- follow-up manual npm/bootstrap commands

The policy should have rejected this before execution, but it did not.

## Cause

The empty-workspace scaffold policy skipped validation when
`recent_scaffold_command_seen` was true. At execution time, the current assistant
tool call had already been appended to the session, so the in-flight scaffold
command counted as "recent" before it was validated.

## Fix Direction

Validate the current first scaffold command directly:

- do not let the in-flight assistant tool call bypass the empty-workspace
  scaffold policy;
- give explicit scaffold examples for framework requests;
- keep deprecated/manual React bootstraps out of the accepted path so the model
  converges on a small Vite React scaffold.
