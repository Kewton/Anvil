## Result

- Outcome: failed before producing a playable game.

## Observed Behavior

The run scaffolded a Next.js app and changed the page heading to `NEON SPACE INVADERS`, but `src/app/page.tsx` still contained the default Next.js starter paragraph, logo, and links. The app was not a game.

After a large truncated edit, focused recovery did activate and restricted the next turn to `Edit` on `src/app/page.tsx`. However, the recovery request included both:

- a system note with an exact compact `<p>` block anchor
- the latest `Read` result containing the full page

The model copied the full file from the `Read` output into `old_string` instead of using the compact paragraph anchor, hit `num_predict=320`, and ended with:

```text
tool_call_format_error: truncated tool call (generate response hit length limit)
```

## Root Cause

Exact-anchor focused recovery was still sending the full latest `Read` exchange for the second post-scaffold slice. With Qwen 3.5, that full-file context became the dominant anchor, so the model attempted a full-file `old_string` even while the policy asked for one compact block.

The previous v2_005 fix made late truncation recovery active again. This incident shows the next instability: once active, the recovery prompt must remove conflicting full-file context when an exact compact anchor is already provided.

## Fix Direction

When focused edit recovery has a deterministic exact anchor for a scaffold slice, send minimal history only. Keep the accepted plan/user context, but omit the full latest `Read` result so the model has one obvious copy target: the compact exact block embedded in the recovery note.

This keeps the fix generic to focused edit recovery and avoids adding task-specific Space Invaders code paths.

## Patch

- `src/agent/loop_run/turn.rs`
  - Added second-slice exact-anchor detection for `app/page.tsx` / `src/app/page.tsx`.
  - Reused minimal focused-edit history whenever first or second scaffold slices already have an exact anchor.
  - Added a regression test proving second-slice exact anchors are detected and no longer apply after later edits.
