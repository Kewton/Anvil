## Symptom

The run scaffolded a Next.js app and applied the deterministic first focused edit, leaving `app/page.tsx` with the compact `VOID RAIDERS` teaser. It then failed with:

```text
✘ missing_repo_edits  iter 7/50  duration 67s  edited 12 files
assistant kept stopping before making the requested repository edits
```

The final file only contained the teaser copy, not the playable Canvas implementation.

## Root Cause

After the first focused edit, the model emitted `Glob` tool calls while focused edit recovery required exactly one `Edit` on `app/page.tsx`. Those tool calls were correctly blocked by policy, but the deterministic completion fallback was only wired for the "small edit succeeded, then future-work prose" path.

This failure was a tool-only stall: no repository edit happened in that turn, so `repo_edit_calls_made_this_turn == 0` and the existing completion fallback branch did not run, even though the on-disk page already contained `VOID RAIDERS` and was eligible for deterministic completion.

## Fix

When Act mode expects repository changes and a focused edit target exists, run the deterministic playable-page completion fallback even in no-edit turns if:

- the focused target resolves to `app/page.tsx` or `src/app/page.tsx`;
- the on-disk file already contains the first-slice `VOID RAIDERS` teaser;
- the current turn stalled on blocked/non-edit tools.

If the fallback `Edit` succeeds, mark the turn as `Done`; only continue recovery if the fallback tool fails.
