# UAT v2 033 incident

- Time: `2026-04-25 12:15:00 JST`
- Model: `qwen3.5:122b` with sidecar `qwen3.5:9b`
- Scenario: exact v2 UAT instruction 3, `Nuxt.js` Tetris game.
- Result: failed before completing the required four-instruction run.

## What Happened

Instructions 1 and 2 produced acceptable deterministic canvas games:

- Space Invaders: `app/page.tsx`, `next dev -p 3011`
- Breakout: `src/App.tsx`, `vite --host 0.0.0.0 --port 3011`

Instruction 3 eventually generated a Nuxt app, but the resulting `app.vue`
implemented a low-fidelity DOM Tetris board. It had state, keyboard handling,
and a start/restart button, but the currently falling piece was not composed
into the visible board. The player could press keys, but the active Tetromino
was not visible while falling, so the game was not a high-quality playable
output.

## Cause

The playable UI quality gate only required generic input, state, and feedback
markers once the output was not an obvious scaffold placeholder. A DOM grid with
`keydown`, `ref`, and `score` markers could pass even when it lacked a real-time
render loop and visible gameplay.

The deterministic fallback also only replaced placeholder or very short
incomplete slices. It did not replace longer but low-fidelity game
implementations.

## Fix Direction

For game requests, tighten the quality gate to require a real-time game surface:

- canvas-based rendering
- `requestAnimationFrame` loop
- direct keyboard or pointer input
- restart/status feedback

If a game output lacks those markers, treat it as a low-fidelity game slice and
allow deterministic playable-UI fallback to replace it with the generic canvas
game template.
