The v2_006 fix avoided the previous full-file `old_string` truncation by omitting the latest full `Read` exchange when an exact compact anchor was already embedded in the recovery note. However, Qwen 3.5 then repeatedly emitted `Read` even though focused edit recovery only allowed `Edit`:

## Root Cause

For exact-anchor recovery, removing the full `Read` history eliminated the long-anchor failure but also removed the model-visible proof that the target file had already been read. The runtime knew the target had been read, but the prompt context no longer contained a recent `Read` result. Qwen 3.5 therefore kept trying to call `Read` before editing.

## Fix Direction

When exact-anchor focused recovery is active, provide a compact synthetic `Read` exchange that contains only the target block, not the full file. This preserves the model-visible "last Read" contract while avoiding the original full-file anchor that caused truncated tool calls.

This remains generic to focused edit recovery: it does not add task-specific Space Invaders implementation paths.

## Patch

- `src/agent/loop_run/turn.rs`
  - Replaced the boolean exact-anchor check with a helper that returns the exact anchor block.
  - Added focused edit request history that includes the accepted plan/user context plus a synthetic compact `Read` result for the anchor block.
  - Added regression coverage for second-slice anchor extraction and the compact synthetic `Read` history.
