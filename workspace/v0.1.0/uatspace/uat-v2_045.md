- 事象
  - `uat-v2_045` の3回目/4回目で auto-plan classifier が `<think>` 付き応答を返し、`WARN auto-plan classifier failed: failed to parse large-task classifier response: <think>...` として内部推論文がユーザー向け出力に漏れた。
  - 3回目では分類失敗後の heuristic fallback が `ui` となり、Nuxt.js アプリ開発指示としては不自然な profile 表示になった。
- 問題箇所
  - `src/agent/loop_run/commands.rs`
    - `parse_large_task_decision` が classifier 応答をそのまま JSON 抽出しており、`<think>...</think>` を正規化していない。
    - parse error 文字列に `reply.content.trim()` を含めており、警告出力にモデルの内部文が露出する。
    - classifier failure を常に `tracing::warn!` で出しており、heuristic fallback で継続できる非致命的 parse failure もユーザー出力に混ざる。
    - heuristic の profile 推定で Nuxt/Vue 等の framework app 指示を coding として強く扱えていない。
- 根本原因
  - local LLM は JSON-only 指示でも `<think>` や説明文を返すことがあるが、classifier 専用の入力正規化と安全なエラー要約が不足していた。
  - fallback 可能な分類失敗を運用上の警告として扱っていたため、E2E 出力品質に直接影響した。
- 対策案
  - classifier 応答は `<think>` 除去後に JSON 抽出する。
  - parse failure のユーザー可視エラーには raw response を含めず、詳細は構造化ログ側だけに保持する。
  - fallback 可能な parse failure は debug ログに下げ、transport error のみ warn とする。
  - framework/game/app 実装の heuristic profile を coding 優先にする。
- 対策案詳細（仕様）
  - `parse_large_task_decision(raw, request_hint)` は `strip_think_tags(raw)` 済み文字列から JSON object を抽出する。
  - parse 不能時の戻りエラーは `classifier response was not JSON-only` の固定文言とする。
  - `maybe_auto_plan_prompt` の `Err` 処理は `is_classifier_transport_error(err)` の場合のみ `warn!`、それ以外は `debug!` とする。
  - `infer_task_profile_from_text` は `next.js/react/nuxt/vue/vite/typescript/javascript/game/web app` および `アプリ/ゲーム/実装/開発/コード` を先に検出して `TaskProfile::Coding` を返す。
