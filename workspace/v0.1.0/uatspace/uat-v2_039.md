- 事象
  - `uat-v2_039` の4指示は完了したが、5-2-1の `npm run dev -- -p 3011` 起動確認後、`curl -I http://localhost:3011` が 500 を返した。
  - dev server は起動し、`Local: http://localhost:3011` までは到達した。

- 問題箇所
  - `src/agent/loop_run/quality.rs`
  - deterministic framework game fallback が `package.json` の依存をすべて `"latest"` で生成していた。

- 根本原因
  - `"latest"` 依存により Next/React/TypeScript の組み合わせが実行時に固定されず、既存環境や現在のレジストリ状態に左右される。
  - 今回は Next 16 系が解決され、既存の node_modules 解決経路と噛み合って `createClientModuleProxy` / `deploymentId` 参照エラーになった。

- 対策案
  - deterministic fallback が生成する Next / Vite React / Nuxt の依存バージョンを、既知の安定組み合わせに固定する。
  - scaffold 後に最小アプリを起動する用途では最新追従より再現性を優先する。

- 対策案詳細（仕様）
  - Next.js fallback:
    - `next = 14.2.35`
    - `react = react-dom = 18.2.0`
    - `typescript = 5.4.5`
    - React / Node 型定義も React 18 / Node 20 系へ固定する。
  - Vite React fallback:
    - `vite = 5.4.11`
    - `@vitejs/plugin-react = 4.3.4`
    - React 18 / TypeScript 5.4 系へ固定する。
  - Nuxt fallback:
    - `nuxt = 3.13.2`
    - `vue = 3.5.13`
    - `typescript = 5.4.5`
  - package生成テストで `"latest"` が混入しないことを検証する。
