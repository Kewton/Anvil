- 事象
  - `uat_056` は Plan 完了後に `yes` で Act に進み、`create-next-app` による Next.js scaffold と `src/app/page.tsx` の Read までは成功した。
  - その後の focused edit recovery 中に `assistant reply timed out after 45s` で停止した。
  - 終了表示は `transport_error iter 4/50 duration 190s edited 12 files`。

- 問題箇所
  - `src/agent/loop_run/turn.rs`
  - `request_assistant_reply_non_streaming` の timeout 算出。
  - `focused_edit_timeout_override_secs` が返す `FOCUSED_EDIT_POST_READ_TIMEOUT_SECS = 45` が、qwen3.5 用の `QWEN35_NON_NATIVE_HARD_TIMEOUT_SECS = 90` より優先されていた。

- 根本原因
  - 前回修正で qwen3.5 を非ストリーミング化し、通常経路のタイムアウトを90秒に固定したが、focused edit recovery の短縮タイムアウト override 経路を見落としていた。
  - focused edit recovery は「対象ファイルを読んだ後は短い編集ツール呼び出しだけを期待する」設計だが、qwen3.5:122b は実際には tool call 生成まで45秒を超えることがあり、短縮値が品質安定化を阻害した。

- 対策案
  - non-streaming の実効タイムアウトを `timeout_override_secs` 単体で決めず、モデル固有の最小タイムアウトを下回らないようにする。
  - qwen3.5 系では focused edit recovery の 30/45 秒 override が指定されても、最低90秒を維持する。
  - qwen3.6 など非 qwen3.5 系では既存の focused edit 短縮を維持する。

- 対策案詳細（仕様）
  - `effective_non_streaming_timeout_secs(model, native_tools_enabled, default_timeout_secs, timeout_override_secs)` を追加する。
  - `model_timeout = non_streaming_assistant_reply_timeout_secs(model, native_tools_enabled, default_timeout_secs)` を算出する。
  - override がない場合は `model_timeout` を使う。
  - override がある場合は qwen3.5 系のみ `max(override, model_timeout)` を使い、それ以外は従来通り override を使う。
  - qwen3.5 の focused edit pre-read/post-read override が90秒になること、qwen3.6 は45秒 overrideを維持することを単体テストで固定する。
