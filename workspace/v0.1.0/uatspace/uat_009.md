## 事象
- `sandbox_0424/uat_009` で UAT を実施したところ、Plan mode Stage 1 の main model request は `assistant reply timed out after 90s` 相当で bounded されたが、retry 後も同じ `qwen3.5:122b` request を繰り返し、plan が前進しなかった。
- セッションログでは `ollama.generate.request(model=qwen3.5:122b, stream=false)` が約 90 秒おきに再発行されていた。

## 問題箇所
- `src/agent/loop_run/turn.rs`
  - hard timeout 後も retry 先が同じ main model のままで、degraded fallback が無い。

## 根本原因
- `qwen3.5:122b` はこの large Plan prompt に対して繰り返し stall しており、bounded retry だけでは進捗を回復できない。
- classifier と summary では sidecar fallback を使っているが、Plan drafting 本体には同様の degraded path が無かった。

## 対策案
- Plan mode で main model が timeout したら、残りの planning は sidecar model に切り替える。
- Act mode は引き続き main model を使い、fallback は Plan mode に限定する。

## 対策案詳細（仕様）
1. `Agent` に plan-mode 専用の assistant model override を持たせる。
2. `assistant reply timed out` が Plan mode で発生し、sidecar が利用可能で、まだ override していない場合は `sidecar` を plan model として採用する。
3. override 中の Plan mode request は sidecar model 名で spinner / request を出す。
4. Plan approval 後に Act mode へ移ったら override は使わず main model に戻す。
5. 回帰防止として、
   - timeout 後の plan model fallback 判定 test
   - Plan mode だけ override が効く test
   を追加する。
