## 事象
- `qwen3.5:122b` で `uat_042` を実施したところ、empty workspace から scaffold と `Read src/app/page.tsx` までは成功した。
- その次の focused turn で `Edit` は完走せず、`tool call parser failed: truncated tool call (generate response hit length limit)` で終了した。

## 問題箇所
- `src/agent/loop_run/turn.rs`
- `src/agent/recovery.rs`

## 根本原因
- focused post-read turn に short timeout / small `max_predict` は効いているが、`qwen3.5:122b` はまだ広い `Edit` を組み立てようとして length limit に到達している。
- 現状の focused note は `exactly one compact Edit` を要求しているものの、default Next page のどこを `old_string` anchor にすべきかが曖昧で、置換範囲がまだ大きい。

## 対策
- scaffold 直後の first `Edit` note をさらに具体化し、default page 全体ではなく対象ブロックだけを置換させる。
- already-read focused edit では、`old_string` anchor を page component の具体的な既存ブロックに固定する。

## 対策案詳細（仕様）
- `app/page.tsx` / `src/app/page.tsx` 向けの scaffold note で、`old_string` は読み取った既存 JSX の特定ブロックだけにするよう明記する。
- `Read` のやり直しや複数 tool call は引き続き禁止し、`Edit` 1 件だけを返させる。
