## 事象
- `uat_043` の対策として、central marketing copy block を exact anchor に指定して `uat_044` を実施した。
- scaffold と `Read src/app/page.tsx` の後、失敗シグネチャは `tool call parser failed: unterminated <anvil_tool_call> block` に変わった。

## 問題箇所
- `src/agent/recovery.rs`
- focused edit 後の tool-call formatting recovery

## 根本原因
- 対象ブロックを狭めたことで model は `Edit` tool call 自体は出し始めたが、XML wrapper か内部 JSON を最後まで閉じ切れなかった。
- つまり問題は「何を編集するか」より、「短い完全な tool call として最後まで出し切るか」に移っている。

## 対策
- `unterminated <anvil_tool_call> block` に対しても focused edit 専用 recovery を追加する。
- note では prose を禁止し、短い `Edit` wrapper を 1 件だけ返すようさらに強制する。

## 対策案詳細（仕様）
- `unterminated <anvil_tool_call> block` かつ `focused_edit_target_already_read(...) == true` の場合は、generic な format retry ではなく focused note を返す。
- note では `Do not call Read again`、`no prose before or after the tool call`、`exactly one compact Edit`、`old_string exactly from the last Read` を明示する。
