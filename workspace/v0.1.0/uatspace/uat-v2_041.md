- 事象
  - qwen3.5:122b の UAT 4 本目「スペースインベーダーゲームをよりカッコよくしてください」で、既存 `src/app/page.tsx` を Read した後の推論が 122 秒、続く Write 後の推論が 159 秒まで伸びた。
  - ESC 割り込みは受理されたが、Ollama 呼び出しが戻るまで停止できず、最終的に `duration 319s edited 0 files` で中断終了した。

- 問題箇所
  - `src/agent/loop_run/turn.rs`
  - `src/agent/loop_run/quality.rs`

- 根本原因
  - 既存のプレイ可能 UI を「よりカッコよくする」改善指示に対して、runtime は通常の LLM 編集ループへ任せていた。
  - 品質 fallback は scaffold / placeholder / 低品質な縦切りを置換する用途に偏っており、すでに合格水準の既存 UI を短く確実に polish して完了する経路がなかった。
  - その結果、モデルが既存ファイル全体を再編集しようとして長時間推論し、タイムアウト後も通常リトライに流れやすかった。

- 対策案
  - 改善指示かつ既存のプレイ可能 UI が品質基準を満たしている場合は、LLM に全面編集を続けさせず、決定的な小規模 polish fallback を適用して完了する。
  - 同じ fallback をタイムアウト時にも適用し、既存 UI 改善タスクが長時間の再推論へ入り続けないようにする。

- 対策案詳細（仕様）
  - `request_is_playable_ui_improvement` を追加し、ゲーム / interactive UI の改善要求を検出する。
  - `deterministic_playable_ui_polish_fallback` を追加し、既存の React / Vue UI に `data-anvil-polish="v1"` と視覚的な背景・光彩・ステージ強調を小さく追加する。
  - placeholder 置換 fallback とは分離し、既存 UI が品質基準を満たしている場合だけ polish fallback を適用する。
  - 1 回適用済みのファイルには再適用しない。
  - Act ループでツール実行後に編集がまだない場合、および LLM timeout 時に polish fallback を試行する。
