- 事象
  - `uat-v2_011` で Space Invaders の Next.js アプリ生成中、`tool_call_format_error` で停止した。
  - 停止時のエラーは `tool call parser failed: truncated tool call (generate response hit length limit)`。
  - 生成途中の `src/app/page.tsx` は見出しだけ `SPACE INVADERS` に変わり、ゲーム実装には到達していなかった。

- 問題箇所
  - `src/agent/recovery.rs`
    - `second_scaffold_shell_edit_exact_anchor_note`
  - `src/agent/loop_run/turn.rs`
    - `focused_edit_exact_recovery_anchor`
    - `focused_edit_second_slice_note`
    - `extract_page_intro_paragraph_from_numbered_read`

- 根本原因
  - 足場作成後の2回目リカバリで、`<p>` ブロック全体を exact `old_string` として再出力させていた。
  - 対象の Next.js デフォルト paragraph はリンクや URL を含む 17 行の大きなブロックで、focused edit の `num_predict=320` では XML tool call の JSON が閉じ切らず、毎回 truncate した。
  - 「小さく編集する」方針と「巨大な exact old_string をコピーさせる」仕様が矛盾していた。

- 対策案
  - 2回目リカバリの exact anchor は paragraph 全体ではなく、paragraph 内の本文1行だけにする。
  - リカバリ指示も「`<p>` intro block」ではなく「intro copy line」として、`new_string` も1行・短文に制限する。
  - paragraph 内に適切な本文行が見つからない場合だけ従来の paragraph 抽出を fallback とする。

- 対策案詳細（仕様）
  - `extract_page_intro_copy_line_from_numbered_read` を追加し、最新 Read 結果から `<p>` 内の最初の非タグ本文行を抽出する。
  - `focused_edit_exact_recovery_anchor` の2回目 slice は `latest_page_intro_copy_line_from_read` を使う。
  - `focused_edit_second_slice_note` も同じ短い anchor を埋め込む。
  - `second_scaffold_shell_edit_exact_anchor_note` は、対象を「already-read intro copy line」に変更し、`new_string` を1行・180文字程度に制限する。
