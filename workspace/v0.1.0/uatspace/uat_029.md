## 事象
- `uat_029` は scaffold 後の recovery target が `app/page.tsx` に固定され、初めて `Edit app/page.tsx` まで到達した。
- ただし変更内容は static shell 1 回だけで、直後の assistant final reply は `Now I'll create the full Space Invaders game...` という future-intent prose だった。
- runtime はこの prose を完了応答として受理し、実際には first slice しか入っていないのに `done` で終了した。

## 問題箇所
- `src/agent/loop_run/turn.rs`
- `src/agent/recovery.rs`

## 根本原因
- `ActionExpectation::RepoChange` では「repo edit が 1 回以上あった」ことだけで success 判定へ進めており、edit 直後の final prose が未完了な next-step 宣言でも reject していなかった。
- そのため post-scaffold first edit を強制する recovery と、completion 判定の間にギャップが残っていた。

## 対策
- repo-change task で repo edit 後の final prose が `Now I'll ...` `Let me ...` `次に ...` などの future-intent なら done にせず retry する。
- retry 時は generic repo-change note ではなく、「small edit は入ったが future work prose で止まるな。次は exactly one tool call で継続せよ」という専用 note を返す。

## 期待効果
- scaffold 後の first slice 1 edit で premature stop する経路を減らせる。
- `uat_029` 型の「small Edit 成功 -> next-step prose -> done」を、追加 implementation turn に押し戻せる。
