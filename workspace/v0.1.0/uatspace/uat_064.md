# uat_064

- 事象
  - qwen3.5 UAT の Act iter 4 で `tool_call_format_error` により停止した。
  - エラーは `tool call parser failed: truncated tool call (generate response hit length limit)`。
  - `src/app/page.tsx` は first scaffold edit により `VOID RAIDERS` の見出しだけ入ったが、完全な playable game へ進まなかった。

- 問題箇所
  - `src/agent/loop_run/turn.rs`
  - `request_assistant_reply_with_retry` の focused edit truncated tool call recovery。
  - `deterministic_page_completion_edit_reply` の発火条件。

- 根本原因
  - first edit 後の completion fallback は `user_task_mentions_space_invaders` を必須にしていた。
  - Plan 承認後の compaction では元のユーザー依頼が `user` role から消え、承認メッセージや compact summary だけが残ることがある。
  - その状態では `src/app/page.tsx` に `VOID RAIDERS` sentinel が存在していても completion fallback が発火せず、qwen3.5 が同じ長大な full-file `Edit` を繰り返して長さ制限で切れた。

- 対策案
  - completion fallback は user message ではなく、対象ファイルに first edit の sentinel が入っているかで判断する。
  - successful edit count は plan compaction や周辺 edit count の揺れに強くするため `>= 1` で completion fallback を許可する。

- 対策案詳細（仕様）
  - `deterministic_page_completion_edit_reply` は page component target かつ現在のファイル内容に `VOID RAIDERS` がある場合に deterministic playable page への `Edit` を返す。
  - focused edit truncated recovery は successful non-plan repo edit が 1 回以上ある場合、deterministic completion fallback を試す。
  - compacted context で original user task が消えても completion fallback が維持される unit test を追加する。
