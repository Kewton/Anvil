# UAT v2 031 incident

- Time: `2026-04-25 11:32:00 JST`
- Model: `qwen3.5:122b` with sidecar `qwen3.5:9b`
- Scenario: v2 UAT run with instructions 1 and 2 passed, then exact instruction 3, `Nuxt.js` Tetris game.
- Result: failed before completing the required four-instruction run.

## What Happened

The agent accepted the Nuxt scaffold command and later created a minimal Nuxt
shell:

- `package.json`
- `nuxt.config.ts`
- `app.vue`

However, `app.vue` only referenced `<TetrisGame />`, and the actual
`components/TetrisGame.vue` implementation was not present on disk. The loop
then entered a long model-thinking turn without producing the missing playable
implementation, so the run had to be stopped.

## Cause

The deterministic playable-UI fallback only replaced files that still contained
known scaffold placeholder markers. A short framework shell that delegates to a
missing component failed the quality gate, but it did not look like scaffold
placeholder content. That left recovery to the model, which was unreliable in
this failure mode.

## Fix Direction

Allow the deterministic playable-UI fallback for incomplete short UI skeletons
as well as obvious scaffold placeholders:

- keep requiring an interactive app/game request before applying the fallback;
- treat very small framework entry files with no interaction markers as
  incomplete playable slices;
- replace those skeletons with the same runnable canvas-based vertical slice
  used for placeholder recovery.
