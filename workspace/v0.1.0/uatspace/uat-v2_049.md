# UAT v2 049 incident

## Context

- Model: `qwen3.6:27b-coding-nvfp4`
- Sidecar: `qwen3.5:9b`
- Run: `/Users/maenokota/share/work/localwork/codextest/sandbox_0424/uat-v2_049`
- Instruction 4: `スペースインベーダーゲームをよりカッコよくしてください。`

## Symptom

The improvement request was classified as a large UI task and entered plan mode. After plan approval, Act mode spent over 100 seconds in normal model execution, including a prose-only retry, before deterministic polish fallback finally applied.

## Cause

Deterministic polish fallback was only checked after tool calls, timeout handling, or later retry paths. For existing playable UI improvement requests, the target file and deterministic polish operation are already known at Act start, but the loop still waited for the main model first.

## Fix

At the start of the Act loop, before requesting the next assistant reply, apply deterministic polish fallback immediately when:

- the current turn expects repository changes,
- no repo edit has been made yet,
- the active request is a playable UI improvement,
- an existing implementation target can be polished.

This keeps the behavior generic for playable UI improvements and avoids framework-specific model retry delays.
