## 事象
- `uat_041` では `Read` 後に pure timeout ではなく、`tool call parser failed: truncated tool call (generate response hit length limit)` で終了した。
- scaffold と `Read src/app/page.tsx` までは同じだが、その先で model が tool call を出し始めた形跡がある。

## 問題箇所
- `src/agent/loop_run/turn.rs`
- `src/agent/recovery.rs`

## 根本原因
- small `max_predict` override により、`qwen3.5:122b` は post-read turn で応答を返し始めたが、まだ large `Edit` を生成しようとして length limit に達した。
- 現状の generic `tool_call_format_recovery_note(...)` は already-read focused edit に対して弱く、`Do not call Read again; exactly one compact Edit` を十分強制できていない。

## 対策
- truncated tool call 時も focused edit 専用 recovery note を使う。
- そのうえで `max_predict` を少し戻し、compact `Edit` 1 件が完走できるだけの余地は残す。

## 対策案詳細（仕様）
- `truncated tool call` かつ `focused_edit_target_already_read(...) == true` の場合は `focused_edit_truncated_tool_call_note(...)` を返す。
- note では `Do not call Read again`、`exactly one Edit`、`old_string exactly from the last Read`、`one contiguous block only` を明示する。
- `max_predict` は timeout に戻らない範囲で少し緩め、small but complete な `Edit` tool call を完走させる。
