## 事象
- `uat_030` は model/tool loop に入る前に停止し、terminal 上は footer の `0% (0 / 24k)` だけが継続表示された。
- sandbox 側にはファイル変更がなく、sample すると main thread は `capture_repo_snapshot()` 内で `/Users/maenokota` 配下を走査していた。

## 問題箇所
- product runtime というより、今回の外部 UAT runner 起動条件

## 根本原因
- PTY 経由で `anvildev` を起動した際、実プロセスの `cwd` が intended sandbox ではなく `/Users/maenokota` になっていた。
- その結果 `config.cwd` / `work_root` が home 扱いになり、初回 `capture_repo_snapshot()` が巨大な home directory を読みに行ってハングした。

## 対応方針
- 以降の external UAT は hidden CLI option `--cwd <sandbox>` を明示し、runner 側の current directory ぶれを無効化する。
- これは UAT harness 側の補正であり、今回の失敗は product quality 判定から除外する。
