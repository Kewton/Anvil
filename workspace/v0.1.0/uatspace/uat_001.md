# 事象
- `uat_001` の E2E で、Plan 完了後に `Act` へ遷移したあと `npx create-next-app@latest . --typescript --tailwind ...` 実行で進行が止まったように見え、2分以上復帰しなかった。
- 進捗表示は `Bash` 実行開始まで出るが、その後は footer の再描画だけが続き、コマンドの待機理由や失敗理由が見えない。

# 問題箇所
- [src/tools/bash.rs](/Users/maenokota/share/work/github_kewton/Anvil-develop/src/tools/bash.rs)
- `create-next-app` のような interactive scaffold command を、そのまま非対話 shell で実行している Bash tool

# 根本原因
- `create-next-app` が non-interactive フラグなしで実行されると、対話プロンプト待ちになることがある。
- Bash tool は `stdin` を `null` にして実行しているため、子プロセスは応答不能な待機状態に入りうる。
- その待機状態を runtime が検知して「interactive scaffold command による停止」として表面化できていないため、ユーザーには単なる停止に見える。

# 対策案
- `create-next-app` 系の scaffold command は実行前に non-interactive へ正規化する。
- 少なくとも `--yes` を補完し、package manager 未指定時は `--use-npm` を補完する。
- あわせて `CI=1` を付与して、対話分岐を極力抑止する。

# 対策案詳細（仕様）
- Bash tool 実行前に command 正規化レイヤを追加する。
- 対象:
  - `npx create-next-app`
  - `npm create next-app`
  - `pnpm create next-app`
  - `yarn create next-app`
- 変換ルール:
  - `--yes` または `-y` が無い場合は `--yes` を付与する
  - `--use-npm|--use-pnpm|--use-yarn|--use-bun` が無い場合は `--use-npm` を付与する
  - 実行環境に `CI=1` を設定する
- 回帰確認:
  - unit test で command 正規化を確認する
  - UAT を再実行し、同じ `create-next-app` 位置で停止しないことを確認する
