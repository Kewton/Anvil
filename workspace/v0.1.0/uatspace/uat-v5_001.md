## Findings

- WorkMode should be treated as runtime control state, not as LLM conversation history.
- The LLM can still produce unsupported tool calls via XML fallback, so mode policy must be enforced at execution time, not only in prompt/tool specs.
- Deterministic fallback remains useful when it is narrow and mode-gated:
  - TypeScript UI: app/game/safe polish only.
  - Python: high-confidence CSV CLI only.
  - Docs: empty README creation only.
  - AnswerOnly: no writes and no Bash.

## Current Limitations

- Mode inference is currently heuristic. It is intentionally small and deterministic, but a future LLM classifier can be added as a sidecar decision if its result is stored in `ModeState` and not appended to user-visible conversation history.
- Docs fallback is intentionally minimal. Existing documentation edits still rely on normal LLM editing flow.
- Python fallback is intentionally limited to CSV CLI; broader Python apps remain normal LLM/tool work.
