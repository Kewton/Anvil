## 事象
- `uat_017` で Plan Stage2 中に `Read` ループが発生した。
- モデルは active plan file の絶対パスを見て「workspace 外なのでアクセスできない」と誤解し、`Read absolute plan path` のあとに `Read plans/plan-xxxx.md` を試し、そのまま stall recovery に入った。

## 問題箇所
- `src/system_prompt.rs`
- `src/agent/loop_run/turn.rs`

## 根本原因
- runtime は plan file が state 配下にあっても同一 filename alias を active plan として正規化できるが、そのルールを prompt 上で十分に説明していない。
- そのためモデルが「project root 外の path は読めない」という通常の repo 直感を優先し、plan file を inaccessible と誤認する。

## 対策案
- Plan mode では active plan file の repository-relative alias を明示し、絶対 path と alias のどちらでも同じ plan file だと伝える。
- さらに「workspace 外に見えても inaccessible ではない」と prompt 上で明言する。

## 対策案詳細（仕様）
- system prompt の Plan mode セクションに以下を追加する:
  - active plan file の alias 例: `plans/plan-1776968332.md`
  - absolute path と alias の両方が同じ plan file を指すこと
  - `outside the workspace` と解釈して探索を増やさないこと
- request build 時にも system note として同内容を追加し、最新 turn で確実に見えるようにする
- 期待結果:
  - Stage2/Stage3 で plan file path 誤認による `Read` ループが減る
  - plan completion が stage ごとに前進し、approval まで到達する
