## 事象
- `uat_037` では `Read app/page.tsx + extra tool` が来ても runtime が `Read app/page.tsx` だけを残して実行できた。
- これにより post-scaffold first turn の salvage は前進したが、その次の `Edit only` ターンで model が長考し続け、品質安定の完了条件には未到達。

## 問題箇所
- `src/agent/loop_run/turn.rs`

## 根本原因
- focused edit recovery は `Read` salvage まではできるようになったが、target read 後の follow-up turn で model が still prose/long-think に寄る。
- 現状は `Do not call Read again; exactly one Edit` の指示だけでは、first compact edit を十分高確率に引き出せていない。

## 対策
- target read 後の turn では generic な no-tool retry ではなく、`old_string` を last Read からそのまま使う 1 block `Edit` をさらに強制する方向で締める。
- 必要なら `focused_edit_history` 側で last Read の target 以外をさらに削り、post-read turn の文脈を最小化する。

## 期待効果
- `Read` 成功後の assistant reply が `Edit` 以外へ逃げる余地をさらに減らせる。
- scaffold 後の first implementation slice が `Read 1 回 -> Edit 1 回` に近づく。
