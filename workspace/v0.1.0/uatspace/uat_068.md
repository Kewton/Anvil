- 事象
qwen3.6:27b-coding-nvfp4 で `uat_068` を実行したところ、Next.js scaffold 後に実装対象ファイルを編集できず `missing_repo_edits` で停止した。

- 問題箇所
focused edit recovery 中、モデルは `src/app/page.tsx` を Read/Edit するよう求められていたが、実際には親ディレクトリ `src/app` を Read し続けた。現行ポリシーは対象ファイル以外の Read を拒否するため、対象ファイル未読のまま deterministic first edit fallback も発火できなかった。

- 根本原因
qwen3.6 は focused edit の復旧指示に対して、ファイルパスではなく親ディレクトリを確認する傾向がある。Anvil 側はこの軽微なパスずれを補正せず、対象ファイルを読む前提の fallback に到達できなかった。

- 対策案
focused edit recovery 中の Read tool call で、指定パスが対象ファイルの親ディレクトリを指す場合は、対象ファイルへの Read に正規化する。

- 対策案詳細（仕様）
`prepare_tool_call` で Read の path を正規化する際、focused edit recovery target が存在し、解決済み path が target の親ディレクトリと一致する場合、tool call の path を target に置き換える。これにより `Read(src/app)` は `Read(src/app/page.tsx)` として実行され、以降の compact Edit または deterministic fallback が成立する。
