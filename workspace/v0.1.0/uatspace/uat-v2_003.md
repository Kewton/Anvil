# UAT v2 Incident 003

## Scenario

- Sandbox: `/Users/maenokota/share/work/localwork/codextest/sandbox_0424/uat-v2_003`
- Command: `anvildev -m qwen3.5:122b -y --sidecar-model qwen3.5:9b --auto-plan`
- Prompt: `あなたが考える最高に面白くかっこいいスペースインベーダーゲームを3011ポートで起動可能なnext.jsアプリとして開発してください。`

## Result

Failed during Act mode after scaffold and the first focused edit. The loop repeatedly entered focused edit recovery and ended with:

```text
tool_call_format_error
tool call parser failed: truncated tool call (generate response hit length limit)
```

## Root Cause

The first microscopic scaffold edit succeeded, but the follow-up focused edit still reused the stale pre-edit `Read` output as its anchor context. The model then attempted a full `src/app/page.tsx` replacement using the old scaffold body as `old_string`. Because focused edit recovery capped post-read generation at `num_predict=320`, the JSON tool call was repeatedly truncated before the `Edit` payload completed.

This was not a single bad model response. The recovery prompt lacked a precise second-slice anchor and allowed an outdated read to remain authoritative after a successful repo edit.

## Fix Direction

- Treat a target `Read` as stale once a successful `Write` or `Edit` happens later in the transcript.
- After the first scaffold title edit, guide the second focused edit to replace only the intro `<p>` block with an exact small anchor.
- Keep the workaround generic for scaffolded page components instead of special-casing the UAT prompt.
