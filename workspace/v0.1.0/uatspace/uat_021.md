## 事象
- `uat_020` の Plan mode で Stage2 / Stage3 の `Write` が成功しても、plan file の前段 section が消えたり、stage が `stage2 -> stage1` に巻き戻ったりして完走が不安定だった。
- 具体的には、Stage2 で `Acceptance Criteria` と `Quality Bar` だけを書いた `Write` が active plan file 全体を上書きし、既存の `Goal / Constraints / Deliverables` を消していた。
- また、モデルが full-document の plan rewrite を返した場合も、runtime は stage-local salvage をせず、そのまま reject または overwrite していた。

## 問題箇所
- `src/tools/registry.rs`

## 根本原因
- plan mode の `Write` は通常のファイル書き込みと同じ overwrite semantics のままで、Stage2 / Stage3 の partial write でも plan file 全体を置き換えてしまう。
- `Edit` も `old_string/new_string` の exact replace 前提のため、モデルが full-document rewrite や section fragment を返すと、stage-local update として救済できない。
- `enforce_plan_stage_scope` は disallowed section を見つけると reject するだけで、allowed section を既存 plan に merge する実行時 salvage がない。

## 対策案
- plan mode で active plan file に対する `Write/Edit` は stage-aware section merge に切り替える。
- payload が full-document でも partial section でも、current stage の allowed section だけ抽出して既存 plan file に merge する。

## 対策案詳細（仕様）
- 対象:
  - `ExecutionMode::Plan`
  - active plan file に解決された `Write` / `Edit`
- 動作:
  - current stage の allowed sections を決める
  - payload から見出し単位で section body を抽出する
  - allowed sections だけを既存 plan file に上書きマージする
  - payload に disallowed sections が含まれていても、allowed sections が取れるなら reject せず無視する
  - `Write` が stage-local fragment の場合も、既存の前段 section を保持したまま更新する
  - `Edit` も plan file では `new_string` ベースの section merge salvage を優先する
- エラー条件:
  - payload から current stage の allowed section を 1 つも抽出できない場合は従来どおり error にする
- 期待結果:
  - Stage2 / Stage3 の partial write で Stage1 内容が消えない
  - full-document rewrite が来ても current stage の section だけ反映される
  - `agent.plan.stage_changed` が不必要に逆戻りしなくなる
