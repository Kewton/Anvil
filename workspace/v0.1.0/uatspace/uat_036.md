## 事象
- `uat_036` では focused edit recovery の multi-tool batch を reject する修正を反映した。
- その結果、post-scaffold 実装ターンで `Read app/page.tsx` を含む複数 tool call がまとめて弾かれ、次ターンでも repository edit に至らず `missing_repo_edits` で終了した。

## 問題箇所
- `src/agent/loop_run/turn.rs`

## 根本原因
- multi-tool batch を reject するだけでは、先頭の正しい `Read app/page.tsx` まで捨ててしまう。
- そのため target read の事実が session history に残らず、次ターンでも `Edit only` 状態へ遷移できなかった。

## 対策
- focused edit recovery 中に先頭 tool call が target 上の正しい `Read` / `Edit` なら、それだけを残して後続の exploratory tool call を切り捨てる。
- 先頭 tool call 自体が不正な場合だけ reject する。

## 期待効果
- `Read target + extra tool` のような batch でも target read を保持できる。
- 次ターンを `Edit only` に押し込みやすくなり、first `Edit` への収束率を上げられる。
