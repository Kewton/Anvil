## 事象
- `uat_013` で Plan は完了し、Act に入って `create-next-app` も成功した。
- その後、モデルが `npx next dev -p 3011 &` と `pkill -f "next dev" ...; npx next dev -p 3011 &` を `Bash` で実行したところ、ターミナル上は `running Bash...` のまま長時間停止した。
- 外側から確認すると、`next-server` は実際には `3011` で listen しており、アプリ自体が止まっていたのではなく、`Bash` ツールの終了待ちが詰まっていた。

## 問題箇所
- `src/tools/bash.rs`

## 根本原因
- `Bash` ツールは `sh -lc <command>` を実行し、その後 `collect_output()` で child の stdout/stderr を EOF まで読み切る設計になっている。
- しかし `next dev -p 3011 &` のような背景起動コマンドでは、background child が shell の stdout/stderr pipe を引き継ぐ。
- そのため shell 本体が終了しても pipe が閉じず、`collect_output()` が EOF を待ち続けて `Bash` ツールが完了しない。
- これは `next dev` に限らず、末尾 `&` を含む background 起動コマンド全般で再発しうる。

## 対策案
- `Bash` ツール側で background 起動コマンドを検出し、stdout/stderr を shell pipe から切り離して実行する。
- 実行結果には `background_pid` とログ出力先を返し、モデルが後続の確認に使えるようにする。

## 対策案詳細（仕様）
1. `command.trim_end().ends_with('&')` を満たすコマンドを background 起動候補として扱う。
2. 末尾の `&` を取り除いた本体コマンドを subshell に包み、`>/tmp/anvil-bash-bg-<pid>-<n>.log 2>&1 &` で起動する。
3. shell 自身は `echo background_pid=$!` と `echo background_log=<path>` を返して速やかに終了する。
4. background 起動のときは child の stdout/stderr pipe が background process に保持されないため、`collect_output()` がハングしない。
5. unit test で以下を確認する。
   - `next dev -p 3011 &` が background wrapper に正規化されること
   - `echo hi` のような通常コマンドは書き換わらないこと
   - wrapper が `background_pid=` と `background_log=` を返すこと
