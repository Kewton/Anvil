- 事象
  - `uat-v2_009` の Space Invaders Next.js 生成中、`app/page.tsx` の CTA テキスト `Deploy Now` を compact anchor として提示した直後に `tool_call_format_error` で停止した。
  - モデルは `old_string` に短いアンカーを指定した一方、`new_string` に React import / hook / component 定義を含む大きな実装断片を出力し、`num_predict=320` の上限で tool call JSON が途中切れになった。

- 問題箇所
  - `src/agent/loop_run/turn.rs`
  - focused edit recovery の compact anchor 経路。

- 根本原因
  - compact anchor は full Read を削って token 圧迫を避ける目的だったが、モデルには「1行だけ見えているので、そこへファイル全体を差し込むべき」と解釈される余地があった。
  - 既存の focused edit guidance は「compact Edit」とは伝えていたものの、`new_string` の具体的な上限、1行アンカーが意図的な抜粋であること、import / hook / component 定義を挿入しないことを明示していなかった。

- 対策案
  - compact anchor を通常の exact anchor と区別し、compact anchor 使用時だけ強い制約ノートを追加する。
  - ノートでは `old_string` は提示された短いアンカーのみ、`new_string` は3行以下かつ240文字未満、import / hook / component 定義 / full-file content 禁止、CTA/placeholder なら短いラベル・コピーだけ差し替えることを明示する。

- 対策案詳細（仕様）
  - `build_request_messages` で `recovery_anchor` と `compact_anchor` を分離して算出する。
  - `compact_anchor.is_some()` の場合、`focused_edit_compact_anchor_note` を system message として追加する。
  - `focused_edit_compact_anchor_note` のユニットテストで、今回必要な制約文言が含まれることを固定する。
